---
title: 'Update Customer'
api: 'POST /customers/{customer_id}'
---

Updates an existing customer's information. You can modify customer details like name, email, metadata, and settings. Note that this endpoint uses POST method, not PATCH or PUT.

## Authentication

Requires a valid API key passed in the `Authorization` header as a Bearer token.

```bash
Authorization: Bearer YOUR_API_KEY
```

## Path Parameters

<ParamField path="customer_id" type="string" required>
  The unique identifier of the customer to update
</ParamField>

## Query Parameters

<ParamField query="expand" type="string[]" optional>
  Expand related objects in the response. Available options:
  - `invoices` - Include customer invoices
  - `entities` - Include associated entities
  - `trials_used` - Include trial usage information
  - `rewards` - Include customer rewards and discounts
  - `referrals` - Include referral information
  - `payment_method` - Include payment method details
</ParamField>

## Request Body

All fields are optional. Only include fields you want to update.

<ParamField body="id" type="string" optional>
  New unique identifier for the customer. Use this to change the customer's ID.
</ParamField>

<ParamField body="name" type="string" optional>
  Customer's name. Set to `null` to clear.
</ParamField>

<ParamField body="email" type="string" optional>
  Customer's email address. Must be a valid email format. Set to `null` to clear.
</ParamField>

<ParamField body="fingerprint" type="string" optional>
  Unique identifier for fraud detection. Set to `null` to clear.
</ParamField>

<ParamField body="metadata" type="object" optional>
  Custom metadata key-value pairs. This will merge with existing metadata, not replace it. To remove a key, set its value to `null`.
</ParamField>

<ParamField body="stripe_id" type="string" optional>
  Stripe customer ID to associate with this customer. Set to `null` to unlink.
</ParamField>

<ParamField body="create_in_stripe" type="boolean" optional>
  Whether to create the customer in Stripe if they don't exist there yet.
</ParamField>

<ParamField body="auto_enable_plan_id" type="string" optional>
  The ID of a free plan to enable for the customer.
</ParamField>

<ParamField body="send_email_receipts" type="boolean" optional>
  Whether to send email receipts to this customer.
</ParamField>

## Response

Returns the updated customer object.

<ResponseField name="id" type="string">
  Customer's unique identifier (updated if changed)
</ResponseField>

<ResponseField name="name" type="string">
  Customer's name
</ResponseField>

<ResponseField name="email" type="string">
  Customer's email address
</ResponseField>

<ResponseField name="created_at" type="number">
  Unix timestamp (in seconds) when the customer was created
</ResponseField>

<ResponseField name="fingerprint" type="string">
  Unique device/hardware identifier
</ResponseField>

<ResponseField name="stripe_id" type="string">
  Stripe customer ID if connected
</ResponseField>

<ResponseField name="env" type="string">
  Environment: `production`, `staging`, or `development`
</ResponseField>

<ResponseField name="metadata" type="object">
  Custom metadata key-value pairs (merged with previous values)
</ResponseField>

<ResponseField name="send_email_receipts" type="boolean">
  Whether email receipts are enabled
</ResponseField>

<ResponseField name="subscriptions" type="array">
  Array of active subscriptions
</ResponseField>

<ResponseField name="scheduled_subscriptions" type="array">
  Array of scheduled subscriptions
</ResponseField>

<ResponseField name="balances" type="object">
  Object mapping feature IDs to their balance information
</ResponseField>

## Notes

- This endpoint uses POST method, not PATCH or PUT
- Metadata is merged with existing values - to remove a key, set it to `null`
- Customer IDs can be changed using the `id` field, but the old ID will no longer work
- Updating the email or name does not affect existing subscriptions or balances
- Changes to Stripe-related fields will synchronize with your Stripe account
