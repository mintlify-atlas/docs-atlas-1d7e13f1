## Overview

This page tracks all significant changes to the Autumn API and platform. We follow semantic versioning and maintain backward compatibility.

<Note>
  Subscribe to our [GitHub releases](https://github.com/useautumn/autumn/releases) to get notified of new versions.
</Note>

## 2026

### February 2026

<AccordionGroup>
  <Accordion title="API Version 1.2 - Feature Breakdown Structure" icon="sparkles">
    **Released:** February 18, 2026
    
    **New Features:**
    - Features now return as objects with `breakdown` arrays
    - Better support for multi-interval features
    - Improved feature representation with detailed usage data
    - CheckResult includes full feature breakdown
    
    **Breaking Changes:**
    - None (backward compatible via version header)
    
    **Migration:**
    See [Migration Guide](/resources/migration-guide) for upgrading from v1.1 to v1.2.
  </Accordion>

  <Accordion title="Enhanced Rate Limiting" icon="gauge">
    **Released:** February 2026
    
    **Improvements:**
    - Added customer-scoped rate limiting for better parallelism
    - Increased track endpoint limits to 10,000 req/sec per customer
    - Added dedicated rate limits for events query endpoints
    - Optimized in-memory rate limiting for high-traffic endpoints
    
    **Details:**
    - Track endpoints: 10,000 req/sec (per customer)
    - Check endpoints: 10,000 req/sec (per customer)
    - Events queries: 5 req/sec (per customer)
    - Attach: 5 req/min (per customer)
  </Accordion>
</AccordionGroup>

## 2025

### December 2025

<AccordionGroup>
  <Accordion title="API Key Security Enhancements" icon="shield">
    **Released:** December 2025
    
    **Improvements:**
    - Enhanced API key generation with 42-character keys
    - SHA-256 hashing for stored keys
    - Key caching with 1-hour TTL for improved performance
    - Environment auto-detection from key prefix
    
    **Security:**
    - Keys are now hashed before storage
    - Only key prefixes are visible after creation
    - Cryptographically secure random generation
  </Accordion>

  <Accordion title="Versioning Architecture" icon="code-branch">
    **Released:** December 2025
    
    **New Features:**
    - Compositional version change system
    - Shared transformation utilities
    - Resource-level version changes
    - Automatic version transformation
    
    **Benefits:**
    - DRY transformation logic
    - Type-safe version handling
    - Easier to maintain backward compatibility
  </Accordion>
</AccordionGroup>

### November 2025

<AccordionGroup>
  <Accordion title="Error Handling Improvements" icon="triangle-exclamation">
    **Released:** November 2025
    
    **New Features:**
    - Standardized error response format
    - Machine-readable error codes
    - Detailed error context in `data` field
    - Consistent error handling across all endpoints
    
    **Error Types:**
    - `RecaseError` for expected/client errors
    - `InternalError` for server-side errors
    
    **Error Codes Added:**
    - Customer errors: `customer_not_found`, `customer_already_exists`
    - Product errors: `product_not_found`, `invalid_product_item`
    - Feature errors: `feature_not_found`, `duplicate_feature_id`
    - Entity errors: `entity_not_found`, `entity_already_exists`
    - Balance errors: `insufficient_balance`
  </Accordion>
</AccordionGroup>

## Breaking Changes

<Warning>
  All breaking changes are versioned and backward compatible via API version headers.
