## Overview

Autumn implements rate limiting to ensure fair usage and protect the API from abuse. Different endpoints have different rate limits based on their expected usage patterns.

## Rate Limit Types

Autumn uses six different rate limit configurations based on endpoint type:

### General Endpoints

Most API endpoints fall under the general rate limit:

<ParamField path="Limit" type="number">
  **1,000 requests** per second per organization
</ParamField>

<ParamField path="Scope" type="string">
  Organization-level (shared across all API keys in your organization)
</ParamField>

Applies to endpoints like:
- Creating/updating products
- Managing features
- Organization settings

### Track Endpoints

<ParamField path="Endpoints" type="array">
  `POST /v1/events`, `POST /v1/track`
</ParamField>

<ParamField path="Limit" type="number">
  **10,000 requests** per second per customer
</ParamField>

<ParamField path="Scope" type="string">
  Customer-level (tracked per customer ID)
</ParamField>

Designed for high-volume usage tracking. Rate limits are scoped per customer to allow parallel tracking across different users.

<Note>
  Track endpoints are optimized for high throughput and use in-memory rate limiting (not Redis-backed) for maximum performance.
</Note>

### Check Endpoints

<ParamField path="Endpoints" type="array">
  `POST /v1/check`, `POST /v1/entitled`, `GET /v1/customers/:customer_id`
</ParamField>

<ParamField path="Limit" type="number">
  **10,000 requests** per second per customer
</ParamField>

<ParamField path="Scope" type="string">
  Customer-level (attempts request body first, falls back to URL parameter)
</ParamField>

High limits for real-time entitlement checks. Essential for fast permission verification in your application.

### Events Query Endpoints

<ParamField path="Endpoints" type="array">
  `POST /v1/events/list`, `POST /v1/events/aggregate`, `POST /v1/query`
</ParamField>

<ParamField path="Limit" type="number">
  **5 requests** per second per customer
</ParamField>

<ParamField path="Scope" type="string">
  Customer-level
</ParamField>

Lower limits for analytics queries to prevent expensive operations from overwhelming the system.

### Attach Endpoint

<ParamField path="Endpoints" type="array">
  `POST /v1/attach`
</ParamField>

<ParamField path="Limit" type="number">
  **5 requests** per minute per customer
</ParamField>

<ParamField path="Scope" type="string">
  Customer-level
</ParamField>

Conservative limits for subscription and checkout operations to prevent abuse.

<Warning>
  The attach endpoint has a 60-second window instead of the standard 1-second window.
</Warning>

### List Products Endpoint

<ParamField path="Endpoints" type="array">
  `GET /v1/products`, `GET /v1/products_beta`, `GET /v1/plans`
</ParamField>

<ParamField path="Limit" type="number">
  **20 requests** per second per organization
</ParamField>

<ParamField path="Scope" type="string">
  Organization-level
</ParamField>

## Rate Limit Headers

Every API response includes rate limit information in the headers:

```http
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 1645564800
```

<ResponseField name="X-RateLimit-Limit" type="number">
  Maximum number of requests allowed in the current window
</ResponseField>

<ResponseField name="X-RateLimit-Remaining" type="number">
  Number of requests remaining in the current window
</ResponseField>

<ResponseField name="X-RateLimit-Reset" type="number">
  Unix timestamp when the rate limit window resets
</ResponseField>

## Rate Limit Exceeded Response

When you exceed a rate limit, you'll receive a `429 Too Many Requests` response:

```json
{
  "message": "Rate limit exceeded",
  "code": "rate_limit_exceeded",
  "retry_after": 1000
}
```

<ResponseField name="retry_after" type="number">
  Milliseconds until you can retry the request
</ResponseField>

## Best Practices

<CardGroup cols={2}>
  <Card title="Implement Backoff" icon="clock">
    Use exponential backoff when you receive 429 responses. Wait for the time specified in `retry_after` before retrying.
  </Card>
  
  <Card title="Batch Requests" icon="layer-group">
    Where possible, batch multiple operations into single requests to stay within limits.
  </Card>
  
  <Card title="Cache Responses" icon="database">
    Cache frequently accessed data like customer entitlements to reduce API calls.
  </Card>
  
  <Card title="Monitor Usage" icon="chart-line">
    Track rate limit headers to understand your usage patterns and avoid hitting limits.
  </Card>
</CardGroup>

## Handling Rate Limits

<CodeGroup>

```typescript TypeScript
async function makeRequestWithRetry(url: string, options: RequestInit, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    const response = await fetch(url, options);
    
    if (response.status === 429) {
      const retryAfter = response.headers.get('Retry-After');
      const waitTime = retryAfter ? parseInt(retryAfter) * 1000 : Math.pow(2, i) * 1000;
      
      await new Promise(resolve => setTimeout(resolve, waitTime));
      continue;
    }
    
    return response;
  }
  
  throw new Error('Max retries exceeded');
}
```

```python Python
import time
import requests

def make_request_with_retry(url, headers, max_retries=3):
    for i in range(max_retries):
        response = requests.get(url, headers=headers)
        
        if response.status_code == 429:
            retry_after = response.headers.get('Retry-After')
            wait_time = int(retry_after) if retry_after else 2 ** i
            
            time.sleep(wait_time)
            continue
            
        return response
    
    raise Exception('Max retries exceeded')
```

</CodeGroup>

## Rate Limit Scopes

<Accordion title="Organization Scope">
  Rate limits are shared across all API keys and users in your organization. This applies to:
  - General endpoints
  - List products endpoints
</Accordion>

<Accordion title="Customer Scope">
  Rate limits are tracked per customer ID. This allows high parallelism when tracking or checking multiple customers. This applies to:
  - Track endpoints
  - Check endpoints
  - Events query endpoints
  - Attach endpoint
</Accordion>

## Development and Testing
