## Overview

Autumn uses conventional HTTP response codes to indicate the success or failure of an API request. Errors include both a human-readable message and a machine-readable code for programmatic handling.

## Error Response Format

All error responses follow this structure:

```json
{
  "message": "Human-readable error description",
  "code": "machine_readable_error_code",
  "data": {
    // Optional additional context
  }
}
```

<ResponseField name="message" type="string" required>
  A human-readable description of the error
</ResponseField>

<ResponseField name="code" type="string" required>
  A machine-readable error code for programmatic handling
</ResponseField>

<ResponseField name="data" type="object">
  Optional additional context about the error
</ResponseField>

## HTTP Status Codes

Autumn uses standard HTTP status codes:

<ParamField path="200" type="Success">
  Request succeeded
</ParamField>

<ParamField path="400" type="Bad Request">
  Invalid request parameters or malformed request body
</ParamField>

<ParamField path="401" type="Unauthorized">
  Invalid or missing API key
</ParamField>

<ParamField path="403" type="Forbidden">
  Valid API key but insufficient permissions
</ParamField>

<ParamField path="404" type="Not Found">
  Resource not found
</ParamField>

<ParamField path="429" type="Too Many Requests">
  Rate limit exceeded
</ParamField>

<ParamField path="500" type="Internal Server Error">
  Something went wrong on Autumn's servers
</ParamField>

## Error Types

Autumn has two main error classes:

### RecaseError

Used for expected errors like validation failures, not found errors, and business logic errors.

```json
{
  "message": "Customer not found",
  "code": "customer_not_found",
  "statusCode": 404
}
```

<Note>
  RecaseError is used for all client-side errors that are expected and recoverable.
</Note>

### InternalError

Used for unexpected server-side errors like database failures or missing configuration.

```json
{
  "message": "An internal error occurred",
  "code": "internal_error",
  "statusCode": 500
}
```

<Warning>
  If you frequently encounter InternalError responses, please contact support.
</Warning>

## Error Handling Examples

<CodeGroup>

```typescript TypeScript
try {
  const response = await fetch('https://api.useautumn.com/v1/customers/cus_123', {
    headers: {
      'Authorization': `Bearer ${apiKey}`
    }
  });
  
  if (!response.ok) {
    const error = await response.json();
    
    switch (error.code) {
      case 'customer_not_found':
        console.error('Customer does not exist');
        break;
      case 'rate_limit_exceeded':
        await sleep(error.data.retry_after);
        // Retry request
        break;
      case 'invalid_api_key':
        console.error('Check your API key configuration');
        break;
      default:
        console.error('Unexpected error:', error.message);
    }
    
    throw new Error(error.message);
  }
  
  const data = await response.json();
  return data;
} catch (err) {
  console.error('Request failed:', err);
  throw err;
}
```

```python Python
import requests
import time

def make_request(customer_id, api_key):
    try:
        response = requests.get(
            f'https://api.useautumn.com/v1/customers/{customer_id}',
            headers={'Authorization': f'Bearer {api_key}'}
        )
        
        if not response.ok:
            error = response.json()
            
            if error['code'] == 'customer_not_found':
                print('Customer does not exist')
            elif error['code'] == 'rate_limit_exceeded':
                time.sleep(error['data']['retry_after'] / 1000)
                # Retry request
            elif error['code'] == 'invalid_api_key':
                print('Check your API key configuration')
            else:
                print(f"Unexpected error: {error['message']}")
            
            raise Exception(error['message'])
        
        return response.json()
    except Exception as e:
        print(f'Request failed: {e}')
        raise
```

</CodeGroup>

## Validation Errors

When request validation fails, you'll receive a 400 error with details about which fields are invalid:

```json
{
  "message": "Validation failed",
  "code": "invalid_request",
  "data": {
    "errors": [
      {
        "field": "customer_id",
        "message": "Required field missing"
      }
    ]
  }
}
```
